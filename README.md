# 📝 Blog Website — PHP & MySQL

A simple full-stack **blog management website** built with **HTML, CSS, PHP, and MySQL**. The project includes a public blog homepage, individual blog pages, a blog editor, contact page, and an authenticated admin panel for managing blogs and viewing users.

> **Preview:** The screenshot below was generated by running the supplied PHP project locally and rendering the homepage with representative sample database records. The UI, CSS, PHP templates, and assets are from the project itself.

## ✨ Features

### 🌐 Public Website

## 🚀 Getting Started

### 1. Requirements

Install the following locally:

- **PHP 7.4+**
- **MySQL 5.7+ / MariaDB**
- Apache, XAMPP, WAMP, Laragon, or another PHP server
- A modern web browser

XAMPP is an easy option for beginners because it bundles Apache, PHP, and MySQL together.

### 2. Clone the Repository

```bash
git clone https://github.com/your-username/your-repository.git
cd BlogWebsite-main
```

Or download the project ZIP and extract it into your local web-server directory.

For XAMPP, the project can be placed inside:

```text
C:\xampp\htdocs\blog
```

### 3. Create the MySQL Database

The application expects a database named:

```text
blog
```

Create it with:

```sql
CREATE DATABASE blog;
USE blog;
```

### 4. Create the `blogs` Table

```sql
CREATE TABLE blogs (
    sno INT NOT NULL AUTO_INCREMENT,
    blog_title VARCHAR(255) NOT NULL,
    blog_description TEXT NOT NULL,
    blog_slug VARCHAR(255) NOT NULL,
    banner_img VARCHAR(255) NOT NULL,
    published_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (sno)
);
```

### 5. Create the `users` Table

The admin pages expect the following fields:

```sql
CREATE TABLE users (
    id INT NOT NULL AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    username VARCHAR(100) NOT NULL,
    email VARCHAR(255) NOT NULL,
    password VARCHAR(255) NOT NULL,
    joined_on TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    user_type VARCHAR(50) DEFAULT 'User',
    user_status VARCHAR(50) DEFAULT 'Active',
    PRIMARY KEY (id),
    UNIQUE KEY unique_email (email)
);
```

For an admin account, store a password hash generated by PHP's `password_hash()` rather than storing a plain-text password.

Example:

```php
<?php
echo password_hash('your-password', PASSWORD_DEFAULT);
?>
```

Then insert the generated hash into the `users.password` column.

### 6. Configure the Database Connection

Open:

```text
partials/_dbconnect.php
```

The default project configuration is:

```php
$server = "localhost";
$username = "root";
$password = "";
$database = "blog";
```

Change these values if your MySQL installation uses a different username, password, host, or database name.

### 7. Start the Server

With XAMPP, start:

- Apache
- MySQL

Then open:

```text
http://localhost/blog/
```

The main homepage is served by:

```text
index.php
```

```text
                                      │
                                      └──► CRUD Operations
```

### Publishing Flow

1. An authenticated user opens the editor.
2. A banner image is selected.
3. The title and article content are entered.
4. PHP validates the submitted fields.
5. The image is saved inside `uploads/`.
6. A slug is generated from the blog title.
7. The blog record is inserted into the `blogs` table.
8. The homepage retrieves the new record with a MySQL query.
9. Visitors can open the generated article page.

## 🔐 Authentication

The admin area uses PHP sessions. After a successful login, the application stores values such as:

```php
$_SESSION["username"]
$_SESSION["email"]
$_SESSION["id"]
$_SESSION["loggedin"]
```

Protected admin pages check whether `$_SESSION["loggedin"]` exists before displaying dashboard content.

Passwords are verified with:

```php
password_verify($password, $row['password']);
```

## ⚠️ Current Limitations

This repository is a learning/project implementation and has several areas that should be improved before production use:

- No SQL dump is included with the original project.
- Database queries are built directly from request/input values in several places.
- SQL injection protection should be improved with prepared statements.
- Blog content is not consistently escaped before output.
- There is no CSRF protection for forms.
- The editor does not currently provide a full rich-text editor.
- Blog editing is not implemented; the admin panel currently focuses on viewing/deleting posts.
- Contact form delivery depends on PHP's `mail()` configuration.
- The original project is not fully responsive across all screen sizes.
- The About page is still a work in progress.
- File upload validation should check MIME type, size, filename safety, and generated filenames.
- Admin authorization can be strengthened with role-based access control.
- Slugs should ideally be unique and generated more safely.

These are useful next steps if you want to turn the project into a production-ready CMS.
